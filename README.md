# QiReader Desktop 0.9.1（非官方）

QiReader 列表可放在左侧或右侧，原文显示在另一侧；隐藏列表时全宽阅读。独立网页视图不是 iframe，无需批量打开浏览器标签页。

这是非官方 Electron 桌面壳，在线加载 QiReader 与文章原网页，不包含 QiReader 网页或服务端源码，与 QiReader 官方没有隶属关系。使用时需要网络及自己的 QiReader 账号。

## Windows 使用

从 [GitHub Releases](https://github.com/xxs9331/qireader-desktop/releases) 下载对应版本的 Windows x64 ZIP，完整解压后打开其中的 `QiReader-Desktop.exe`。请保留同目录的所有文件，不能只复制 exe。可自行为 exe 创建桌面快捷方式。

当前提供 Windows x64 便携版，尚未签名，系统可能提示未知发布者。下载可用 Release 中的 `SHA256SUMS.txt` 校验。更新时关闭旧版程序，再解压到新目录；不要删除下方说明的应用数据目录，登录和统计记录会继续保留。

## 顶部阅读进度

顶部居中显示进度，点击周期按「今日 → 本周 → 全部」循环切换，本周从本地时间周一开始。日目标默认手动设为 100 篇；周目标默认自动统计本周收录的稍后阅读文章总数。右上角唯一的 ⚙「设置」统一管理阅读目标和 Cubox 收藏配置。在「阅读目标」中分别设置日、周目标（1–10000 篇），勾选「自动统计」则按当前周期的稍后阅读文章统计，关闭后使用手填篇数。周目标的自动模式不是日目标乘以 7。点击「保存阅读目标」保存；直接关闭窗口会放弃尚未保存的修改。设置按账号保存在本机，重启保留，编辑目标不发起网络请求，且不要求配置 Cubox API。

手动目标按本机确认完成的日期累计，阅读以前收录的文章也能达标；同一篇文章在当前周期最多计一次，重新加入不扣除已经完成的目标进度。达到目标显示「已达标」，超额完成保留实际数量，进度条最多填满。每天本地零点、每周一自动进入新周期。旧版本没有记录完成日期，因此无法补算到日／周手动目标，原来的历史完成进度继续保留。其他设备的移出不能确定实际完成日期，也不会猜算到手动目标。

自动模式按 QiReader 的收录时间 `crawledAt` 划分今日／本周，不是发布时间或加入标签的时间；分母包含本周期已记录的待看和已完成文章。「全部」仍显示所有已记录文章的历史完成进度。三个范围都显示进度条，点击计数手动同步。鼠标悬停可查看口径及最近同步时间；自动模式的「往期」可打开以前收录、仍待看的文章。

QiReader 加入稍后阅读时可能已将文章标为已读，因此这里以「移出稍后阅读」计为完成，包括手动移出。自动移出须获服务器确认才增加完成数；回看不重复计数，重新加入后在自动模式和全部进度中恢复待看。已完成文章持续保留在全部总数中。

本机阅读完成立即更新本地进度；手动修改标签时，只核对发生变化的那一篇。启动时验证当前账号，距离上次完整同步不足 24 小时则直接使用本地统计。取消后台定时扫描和窗口切回时的全量扫描。其他设备新增或移出的文章在下次全量同步后体现，可以点击计数手动同步，两次全量尝试至少间隔 30 分钟。本机统计额外发出的列表分页请求每天最多 100 次，为正常网页浏览留出额度；此上限不包含 QiReader 网页自身和其他设备的请求。收到 HTTP 429 后，统计请求暂停至少 24 小时，服务端要求更久则等待更久；期间不会自动重试。冷却、预算和暂停状态跨重启保留。

本机保存文章 ID、收录时间、完成状态和请求保护状态，按站点与账号分别存储于应用数据目录的 `reading-progress.json`，关闭重开仍保留。首次启用前或程序未记录期间已经加入又移出的文章无法补回，数字表示已记录范围，不代表完整历史流水。没有记录、没有文章、同步失败会分别显示，不会把接口失败当成全部读完。

完整分页成功后才更新总数；网络或格式错误保留上次结果并标记待同步。文章打开时先记录其统计信息，若统计信息无法确认则仍展示原文、暂时保留稍后阅读条目并提示重试，避免先移出后丢失总数。统计接口均只读，移出仍使用原生控件。

## 阅读操作

1. 顶部不再显示「稍后阅读」按钮；在 QiReader 原生列表中选择文章即可。点击文章或在条目上按 Enter/o，保持当前的列表显示状态，不自动收起，也不在失败后自动展开。
2. 在稍后阅读列表中，原文加载成功后自动触发 QiReader 原生移除动作；其他列表不自动移除。原文加载失败或 HTTP 4xx/5xx 时不移除。移除由服务器确认，不直接调用私有写接口。
3. 「列表置右／列表置左」切换列表位置，保留宽度和当前的展开状态。默认 280px，拖动两栏之间的细分隔线调整，可窄至 180px；右侧列表向左拖会加宽。分隔线也支持键盘左右箭头。拖动期间显示当前页面临时预览，松开恢复网页交互，预览不存盘。
4. 左上角 ▾/▸ 手动控制列表，隐藏时原文全宽显示。仅列表关闭且已打开文章时，左下角显示悬浮 ←/→ 切换上一篇/下一篇；展开列表后隐藏悬浮控件，使用列表内的原生翻篇按钮。悬浮控件只占自身的小区域，不预留整条底栏；已移出的文章可以回看，不会再次切换稍后阅读状态。
5. 阅读顺序取自选择文章时的列表，并随着新条目渲染补充。当前原文加载成功后，后台预加载接下来两篇；切到已就绪的文章直接复用页面，仍在加载的继续等待同一次加载，预加载失败则前台重试。点击其他文章会开始该列表的新一轮顺序；手动刷新列表会重置本轮历史。翻篇和预加载不额外请求 QiReader 私有分页接口，列表尚未加载的更远条目需先加载。
6. 两边分别用「字号 − / 百分比 / ＋」调整网页缩放，范围 50%–200%。百分比按钮恢复 100%；页面获得焦点后也可 Ctrl +/−/0 或 Ctrl + 滚轮。缩放包含文字和网页布局，不改网站字体设置；当前窗口内跨文章保留，尚未跨程序重启保存。
7. 错误提示暂时替换顶部统计，点击关闭后恢复进度条。移除失败且条目恢复后可重新点选该文章重试；移除未确认时应先通过原生列表或重新打开程序核对，不凭列表的临时消失判断服务端成功。

## 当前范围

- 从列表标题读取原文地址，不触发 QiReader 原生文章页。原生收藏、复选框和操作按钮保留原行为。没有有效原文链接时保留 QiReader 原生打开方式。
- 自动移除仅作用于 `/tags/!readlater` 当前列表；加载期间切换列表或原条目已被虚拟滚动替换时，不操作其他条目。用户原有 Chrome 扩展队列不参与此流程。
- 同时最多保留当前原文及后续两个后台网页视图。切换范围、刷新列表、登录弹窗或关闭窗口会释放相应预加载页面；后台页面静音、禁止新窗口，保留浏览器沙箱。回到列表点击同一篇可重新加载。列表位置、宽度与缩放在当前窗口内保留，尚未跨程序重启保存。
- 预加载会使用已有站点会话提前访问后续文章，增加最多两个网页的内存及网络开销，可能被文章来源站点记为访问；它本身不触发 QiReader 移出或完成计数。统计记录和服务器移出确认仍在真正选中文章后执行，预加载未完成或这些请求较慢时仍需等待。本版不提供离线正文归档。
- 登录 Cookie 和站点存储持久化；原站点的会话过期规则仍然适用。
- 外部网站不开放 Node.js 或本地系统 API；保留浏览器沙箱、同源限制和 TLS 校验。
- 本版没有移植 Quick Tags，也不读取、迁移、清空 Chrome 扩展队列。
- 相机、麦克风、通知等额外权限默认拒绝。

尚未增加分类快捷键、置顶小窗、自动更新或正文提取器。直接访问 QiReader 文章路由或无原文链接时仍保留原生正文作为兜底，该兜底不自动移除稍后阅读。

顶部「收藏」通过 Cubox 官方 API 提交当前文章。首次点击会打开统一设置窗口，在「Cubox 收藏」部分填写链接：从 Cubox「偏好设置 → 扩展与自动化 → API 扩展」复制完整 API 链接并粘贴；可选默认收藏夹和标签。以后可用右上角同一个齿轮修改或清除本机收藏配置。点击「保存收藏设置」不会修改阅读目标。API 链接是凭据，请只填在软件设置中，不要发到聊天或提交到 GitHub。

配置使用系统安全存储加密，保存在用户数据目录的 `cubox-settings.json`，不会交给文章网页。系统安全存储不可用时拒绝保存。请求使用独立会话，不携带 QiReader／知乎登录 Cookie。点击才提交，不会自动收藏预加载文章。

「已提交」表示 API 接收成功，正文解析由 Cubox 后台完成；需登录的知乎内容不保证完整。失败或超时会提示，超时后请先去 Cubox 核对，避免重复收藏。本次运行内会阻止重复提交同一网址，重启后不查询 Cubox 收藏库。API 权限和每日额度由 Cubox 账号决定（[官方说明](https://help.cubox.pro/save/89d3/)）。保留「外部打开」作为浏览器插件入口。

## 开发与验证

需要 Node.js 22.12+。

```sh
npm ci
npm start
npm test
npm run test:browser
npm run package:win
```

Windows 隔离回归可用 PowerShell 执行 `test/windows-smoke.ps1 -RuntimeZip <electron-v45.0.0-win32-x64.zip 的完整路径>`；使用 Electron 官方 Windows 运行时 ZIP，测试会创建并清理独立临时配置。

浏览器测试运行真实 Electron，使用隔离临时配置及模拟 QiReader/原文响应，不接触个人账号。覆盖文章联动、SPA 延迟渲染、IPC 来源验证、危险 URL 拒绝、双栏布局、登录弹窗、加载失败恢复、进程重启后的存储保留和窗口释放。测试截图在 `artifacts/smoke-平台名.png`。

模拟页面测试不能证明线上 QiReader DOM 和知乎登录兼容性。发布前应在 Windows 实测：选择多篇文章、切换列表、知乎登录及评论、关闭重开程序。不要将模拟测试描述为真实账号验收。

应用依赖 QiReader 当前 DOM 中的 `data-is-entry` / `data-is-entry-title` 列表标记；直接进入文章路由时用 `articleView`、`data-article-url` 兜底。页面改版时调整 `reader-preload.cjs`。未改写网页网络请求。

Windows 包暂未签名。正式包应用数据位于 `%APPDATA%/QiReader Desktop`，请不要删除此目录来更新软件。
